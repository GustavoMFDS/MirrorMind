# Model card — fictional retail release-aware baselines

## Status and intended use

This card covers two fixed one-day heuristics used by the experimental local [`retail release evaluator`](../M1_RETAIL_SYNTHETIC_EVALUATION.md): lag-seven seasonal naive and trailing mean over the previous seven calendar days. The example is a code and data-flow demonstration, not a fitted model, deployed forecast, inventory recommendation or estimate of real retailer performance.

## Evaluation data and temporal protocol

The [fixture card](../datasets/SYNTHETIC_RETAIL_RELEASE_EVALUATION.md) documents the generated 35-day workbook and caller-declared releases. The default evaluation uses a fixed last-seven-calendar-day holdout and a fixed day-35 cutoff. Each target is scored only if its positive product-day exists and its declared release is no later than the final cutoff. The preceding seven consecutive calendar dates must each have positive projected rows declared available by the immediately preceding origin. `InvoiceDate` supplies event time only.

Both baselines receive exactly the same eligible target origins. Missing targets, targets unpublished at the evaluation cutoff and origins with unavailable history receive distinct receipts and never become zero-valued observations. Fewer than two scored origins yields null metrics and no winner. The holdout and release rules are not tuned on empirical data; all fixture values and declarations are hand-constructed.

## Baselines and metrics

- **Seasonal naive:** use the value from seven calendar days before the target.
- **Trailing mean:** average the same seven prior daily values.
- **MAE:** mean absolute error over the matched scored targets.
- **RMSE:** square root of mean squared error over those same targets.
- **Bias:** mean of prediction minus target.
- **WAPE:** sum of absolute errors divided by the sum of positive target units; undefined denominators remain null.

The comparison helper returns a lower-MAE label only when at least two matched targets are scored. That label is descriptive for the constructed fixture and does not select a production model.

## Uncertainty and known limitations

No prediction intervals, residual calibration, distributional assumptions, confidence levels or calibrated coverage are provided. The evaluator does not train or tune either baseline. Positive invoice-line units are not complete demand, missing event days are not zero sales, and caller-declared release dates are not authenticated. A stable SHA-256 binds generated bytes but not the source publisher or its permission.

The [unit release-backtest regressions](../../../tests/unit/test_retail_release_backtest.py) cover the lower-level matched-origin arithmetic and abstention cases. The [integration regressions](../../../tests/integration/test_retail_synthetic_evaluation.py) cover the evidence-to-evaluation composition, stable CLI output, cutoff agreement, withheld-target mutation and no-metric abstention. The suite does not establish empirical predictive skill, forecast uncertainty or suitability for inventory decisions.

## Reproduction and change control

```bash
uv run --no-sync --extra dev python -m examples.m1_retail_synthetic_evaluation --holdout-days 7
python -m pytest -q tests/unit/test_retail_release_backtest.py
python -m pytest -q tests/integration/test_retail_synthetic_evaluation.py
```

When the baseline, split, eligibility rule or score changes, update this card, the fixture card, the evaluator guide and their cited tests together. Keep the holdout fixed for a given fixture version and add an explicit version when intentionally changing the synthetic protocol.
