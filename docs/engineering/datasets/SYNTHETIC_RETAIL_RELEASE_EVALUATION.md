# Synthetic retail release-evaluation fixture card

## Identity and purpose

- **Classification:** fully fictional, generated in memory by [`m1_retail_synthetic_evaluation.py`](../../../examples/m1_retail_synthetic_evaluation.py).
- **Purpose:** exercise the bounded UCI-shaped workbook reader, review-only evidence flow, explicit release checks and fixed-split baseline evaluator together.
- **Rights:** no external dataset or copied UCI record is used. The UCI-shaped headers are a parser contract, not a claim that the fixture is from UCI.
- **Distribution:** this card documents fixture semantics only. It does not authorize acquiring or processing the original Online Retail dataset.

## Construction and schema

The example writes 34 positive invoice-line records over a 35-calendar-day interval beginning 2011-01-01. One event day is intentionally absent. Product, invoice, customer, description and country values are generated placeholders; unit prices are arbitrary and are not used for revenue or demand claims. The projection retains only positive product-day unit totals.

The generator fixes workbook document metadata, normalizes the library-written `modified` timestamp, sorts ZIP members and normalizes ZIP timestamps and compression before computing SHA-256. This makes the demonstration receipt stable under the same Python/openpyxl/zlib toolchain. The digest establishes byte identity for the generated bytes only; it is not publisher provenance.

## Availability-time declarations

Every projected product-day receives a separate, explicit fixture release date. Most are available on the same fictional calendar day; the day-27 value is delayed until day 30, and the final day-35 target is released on day 36, after the day-35 evaluation cutoff. These declarations are designed negative controls. They are not inferred from `InvoiceDate` and do not represent an actual publisher's release history.

The declared calendar covers all 35 dates, while the projected rows intentionally omit one date. No zero is created for the missing event day. The seven-day holdout covers days 29–35; unavailable history and target cases are retained as per-origin statuses.

## Privacy, retention and limits

The workbook exists only in memory and is not written to disk or sent over a network. The generated invoice and customer placeholders are supplied to prove that the reader projection and aggregate receipts omit these fields. No real person, retailer or customer record is represented.

Positive invoice-line units are not complete demand observations. The fixture has no opening calendar, stock, lost sales, returns reconciliation, independently verified publication time, legal source review or empirical forecasting value. See the [UCI source review](UCI_ONLINE_RETAIL_SOURCE_REVIEW.md) before any real-source proposal.

## Reproduction

```bash
uv run --no-sync --extra dev python -m examples.m1_retail_synthetic_evaluation --holdout-days 7
python -m pytest -q tests/integration/test_retail_synthetic_evaluation.py
```

The integration test compares repeated CLI JSON and mutates the unpublished final target. Those checks prove deterministic fixture behavior under the test toolchain and cutoff logic, not source authenticity or real-world completeness.
