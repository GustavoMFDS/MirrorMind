# Architecture Decision Log — 2026-11-17

Status: **Accepted**, **Proposed**, **Deferred**. Accepted describes design intent, not a completed feature.

| ID | Status | Decision | Rationale |
| --- | --- | --- | --- |
| MM-001 | Accepted | MirrorMind is general-purpose decision intelligence; retail is first reference adapter. | Demonstrate a concrete case without domain lock-in. |
| MM-002 | Accepted | Evidence, forecast and simulation remain separate bounded responsibilities. | Avoid false certainty and misleading causal claims. |
| MM-003 | Accepted | WorldKernel is fully independent and accessed through versioned gateway contracts. | Multiple clients and independent release lifecycle. |
| MM-004 | Accepted | LLM orchestrates tools; statistical/ML models generate numeric forecasts. | Grounding, reproducibility and audit. |
| MM-005 | Accepted | Treat model-call cost and simulation compute cost as separate, enforceable budgets. | Production engineering and safety. |
| MM-006 | Accepted | Provenance, source permissions, temporal leakage controls and human approval are core requirements. | Data and operational trust. |
| MM-007 | Proposed | LangGraph, PostgreSQL, pgvector, Redis workers, StatsForecast and OpenTelemetry. | Candidates, not irrevocable dependencies. |
| MM-008 | Accepted | Modular monolith for MVP before splitting services. | Scope and operational simplicity. |
| MM-009 | Deferred | Production claims, hosting and real-company integrations (licensing resolved separately by MM-023). | Require evidence, tests and owner decisions. |
| MM-010 | Accepted | Starting demonstration: replenishment-policy comparison under forecast uncertainty. | Measurable without pretending to estimate price-promotion causality. |
| MM-011 | Accepted | Source uses one installable Python package: thin HTTP routes in `api/`, shared contracts in `core/`, independent feature modules in `modules/`, and tests split by unit/integration boundary. | Keep the modular monolith extensible without premature microservices or empty feature trees. |
| MM-012 | Accepted | Prepare two independent source-research lanes in sequence: UCI Online Retail #352 event-time retrospective, then aggregate Census release-vintage evaluation; preparation does not authorize real-source acquisition/processing, M5 remains NO-GO, and `InvoiceDate` is never treated as publication availability. | UCI product-level rows and Census aggregate release vintages answer different questions; privacy, permissions and temporal evidence must remain source-specific. Owner direction and follow-up evidence recorded in [PR #57](https://github.com/GustavoMFDS/MirrorMind/pull/57#issuecomment-7164856818), [comment 7167002881](https://github.com/GustavoMFDS/MirrorMind/pull/57#issuecomment-7167002881) and [comment 7169397485](https://github.com/GustavoMFDS/MirrorMind/pull/57#issuecomment-7169397485). |
| MM-013 | Accepted | Keep WorldKernel one-way and optional; M1E-02 executes the trusted synthetic inventory demo and M1E-04 may execute one code-owned MirrorMind policy handler in the fixed local worker at an exact reviewed source SHA. No HTTP execution, arbitrary code, production/sandbox claim or edit to the independent repository follows from this decision. | Test each versioned exchange against the pinned engine without making API/core depend on WorldKernel or conflating the demo with the policy model. Owner-approved local scope, 2026-11-25. |
| MM-014 | Accepted | While GitHub Actions is unavailable because the owner reports the allowance exhausted and disallows paid usage or a higher spending limit, use the documented exact-clean-head six-check local gate, independent review and a separate integrated-candidate gate. Preserve check definitions and protections; local evidence is never CI evidence. | Continue safe work within the approved budget. Owner direction and diagnostic follow-up recorded in [PR #57](https://github.com/GustavoMFDS/MirrorMind/pull/57#issuecomment-7164856818), [comment 7164870326](https://github.com/GustavoMFDS/MirrorMind/pull/57#issuecomment-7164870326) and [comment 7169397485](https://github.com/GustavoMFDS/MirrorMind/pull/57#issuecomment-7169397485). |
| MM-015 | Accepted | For the synthetic M1 policy path, register one fixed MirrorMind-owned WorldKernel handler under a code-owned name and revision, compare all engine outcomes with the existing synthetic reference rules, and expose selection only through an explicit local CLI option. | The pinned engine supports trusted code registration, while its bundled immediate-replenishment demo cannot represent M1E-03 lead times and policy semantics. The handler remains optional, experimental, fictional-input-only and outside the HTTP route; no change is made to the independent WorldKernel repository. Owner direction, 2026-11-25. |
| MM-016 | Accepted | Preserve `DecisionTrace` v1 payload compatibility and emit a distinct v2 trace for the composed workflow, linking each outcome to the selected engine result and recording reference-parity execution separately. | Outcome provenance must identify the engine that supplied selected metrics. A parity-oracle invocation is not itself the selected result source; linked canonical digests make this relationship replayable without claiming signatures or independent scientific validation. Owner direction, 2026-11-25. |
